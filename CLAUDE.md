# ring-resonator-toolkit

Python-пакет для проектирования, моделирования (Lumerical FDTD) и анализа кольцевых резонаторов.

## Окружение

- Python 3.12, виртуальное окружение `.venv` (должно быть активировано до запуска `claude`).
- Проверки перед коммитом: `pytest -q` и `ruff check ring_toolkit tests`.
- Lumerical доступен только на отдельной Windows-машине. На этой машине `run_ring` не запускается.
- Git: feature-ветка -> PR -> squash-merge, conventional commits.

## Анализ свипов

- Свипы лежат в `sweeps/<имя>/run_*` (контракт данных — `ring_toolkit/sweep_io.py`).
- Разбор свипа всегда делегируй субагенту `sweep-analyst`. Не анализируй спектры сам.
- Результат субагента передавай пользователю как есть: те же числа, те же формулировки аномалий.
- Собственные соображения (гипотезы о причинах, физическая интерпретация, рекомендации
  по перезапуску) допустимы только в отдельном блоке с заголовком
  «Комментарий основной сессии (не результат анализа)» и никогда не попадают в `report.md`.
- Субагент файлов не пишет. Он возвращает текст отчёта между строками `<<<REPORT` и `REPORT>>>`.
  Запиши этот текст в `<папка_свипа>/report.md` дословно, без маркеров и без своих правок.
  Если маркеров в ответе субагента нет — не составляй отчёт сам, сообщи об этом пользователю.

## Чего не делать

- Не вычислять Q, FSR, n_g вне функций `ring_toolkit.analysis`.
- Не менять дефолты `estimate_q` и `find_resonances` без явной просьбы: от них зависят проверки в `ring_toolkit/analyze.py`.
